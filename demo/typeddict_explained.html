📖 TypedDict trong Python - Giải Thích Chi Tiết

💡 TL;DR - TypedDict là gì?

TypedDict là cách để định nghĩa type hints cho dictionary trong Python.

  • ✅ Dict thông thường: {"name": "John", "age": 30} - Không biết keys nào, type gì
  • ✅ TypedDict: Khai báo rõ ràng keys và types - IDE/mypy check được lỗi
  • 🎯 Lợi ích: Type safety, autocomplete, documentation

Trong LangGraph: TypedDict định nghĩa structure của State chia sẻ giữa các nodes.

📚 1. Vấn Đề: Dict Thông Thường

❌ Dict không có type hints

# Dict thông thường - Không rõ structure user = { "name": "John", "age": 30, "email": "john@example.com" } # Vấn đề 1: Typo không bị phát hiện print(user["naem"]) # KeyError ở runtime ❌ # Vấn đề 2: Không biết keys nào available user["????"] # IDE không suggest được # Vấn đề 3: Type không rõ ràng user["age"] = "thirty" # Sai type nhưng không warning ❌
⚠️ Vấn đề:
  • Không có autocomplete
  • Lỗi chỉ phát hiện ở runtime (khi chạy code)
  • Khó maintain code lớn

✅ 2. Giải Pháp: TypedDict

TypedDict - Dict với type hints

from typing import TypedDict # Định nghĩa structure của dict class User(TypedDict): name: str age: int email: str # Sử dụng user: User = { "name": "John", "age": 30, "email": "john@example.com" } # ✅ IDE autocomplete print(user["name"]) # IDE suggest "name", "age", "email" # ✅ Mypy phát hiện lỗi typo print(user["naem"]) # Error: Key "naem" not found ✓ # ✅ Mypy phát hiện lỗi type user["age"] = "thirty" # Error: Expected int, got str ✓
✅ Lợi ích:
  • IDE autocomplete keys
  • Mypy/Pylance check lỗi trước khi chạy
  • Self-documenting code

🆚 3. So Sánh: Dict vs TypedDict

❌ Dict Thông Thường

# Không type hints user = { "name": "John", "age": 30 } # Function nhận dict def greet(user: dict): # ❌ Không biết user có key gì return f"Hello {user['???']}"

IDE không giúp gì được!

✅ TypedDict

# Có type hints class User(TypedDict): name: str age: int user: User = { "name": "John", "age": 30 } # Function nhận TypedDict def greet(user: User): # ✅ Autocomplete: "name", "age" return f"Hello {user['name']}"

IDE suggest keys + check types!

📝 4. Syntax Chi Tiết

Cách 1: Class Syntax (Khuyến nghị)

from typing import TypedDict, Optional class Person(TypedDict): name: str # Required field age: int # Required field email: Optional[str] # Optional field (có thể None) # Sử dụng person: Person = { "name": "Alice", "age": 25, "email": "alice@example.com" }

Cách 2: Functional Syntax

# Ít dùng hơn Person = TypedDict('Person', { 'name': str, 'age': int, 'email': str })

⚙️ 7. TypedDict Features

🔒 Required vs Optional

class User(TypedDict): name: str # Required age: int # Required email: Optional[str] # Optional # ✅ OK user = {"name": "A", "age": 20} # ❌ Error: Missing "name" user = {"age": 20}

📦 total=False

# Tất cả fields đều optional class User(TypedDict, total=False): name: str age: int # ✅ OK - Không cần đủ keys user = {"name": "A"} user = {}

🔗 Inheritance

class BaseUser(TypedDict): name: str age: int class AdminUser(BaseUser): role: str permissions: List[str] # AdminUser có: name, age, role, permissions

🎯 Annotated

from typing import Annotated class State(TypedDict): # Metadata cho field messages: Annotated[ List[BaseMessage], operator.add # Reducer ]

🎬 8. Runtime Behavior

⚠️ Lưu Ý Quan Trọng

TypedDict KHÔNG validate ở runtime!

TypedDict chỉ dùng cho static type checking (mypy, Pylance). Ở runtime, nó vẫn là dict thông thường.

class User(TypedDict): name: str age: int # ❌ Mypy warning (static check) user: User = {"name": "John", "age": "thirty"} # ✅ Nhưng code VẪN CHẠY được (runtime) print(user) # {'name': 'John', 'age': 'thirty'} # Runtime check: Phải dùng thư viện khác from pydantic import BaseModel # Validate ở runtime
📌 So Sánh:
Tool Type Check Runtime Validate
TypedDict ✅ Static (mypy) ❌ Không
Pydantic ✅ Static ✅ Runtime
dataclass ✅ Static ❌ Không (trừ khi dùng validator)

💡 10. Khi Nào Dùng TypedDict?

✅ Nên Dùng TypedDict Khi:

  • Làm việc với dict có structure cố định
  • Cần type hints nhưng không cần runtime validation
  • Data cần serialize/deserialize thường xuyên (JSON, DB)
  • Muốn dict-like access: obj["key"]
  • LangGraph State: Chia sẻ data giữa nodes

❌ Không Nên Dùng TypedDict Khi:

  • Cần runtime validation → Dùng Pydantic
  • Cần object với methods → Dùng dataclass
  • Cần immutability → Dùng NamedTuple hoặc frozen dataclass
  • Dict structure thay đổi liên tục → Dùng dict thông thường

🎯 11. Best Practices

✅ DO

  • Dùng class syntax
  • Document fields
  • Dùng Optional[] cho nullable
  • Group related fields

❌ DON'T

  • Expect runtime validation
  • Quá nhiều nested TypedDict
  • Dùng cho dynamic dict
  • Mix với Pydantic Models
# ✅ GOOD: Rõ ràng, có doc class UserProfile(TypedDict): """User profile data structure""" user_id: int # Unique identifier username: str # Display name email: Optional[str] # Contact email (optional) created_at: str # ISO datetime string # ❌ BAD: Không rõ ràng class Data(TypedDict): a: str b: int c: Optional[List[dict]] # dict gì? Structure ra sao?

🎓 Kết Luận

TypedDict là công cụ đơn giản nhưng mạnh mẽ để thêm type safety cho dict trong Python. Nó giúp code dễ đọc, dễ maintain, và IDE/mypy có thể catch bugs sớm.

Trong LangGraph, TypedDict định nghĩa contract cho State - tất cả nodes đều biết structure, types, và có thể làm việc an toàn với shared state!

💡 Remember: TypedDict = Dict + Type Hints. Nó KHÔNG thay đổi runtime behavior, chỉ giúp static type checking!
