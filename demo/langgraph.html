LangGraph

Framework xây dựng AI Agent dạng đồ thị trạng thái (Stateful Graph)

Built on top of LangChain

🧠 LangGraph là gì?

LangGraph là một thư viện Python (và JS) cho phép xây dựng AI Agent dạng đồ thị có trạng thái (stateful graph). Thay vì chạy một chuỗi prompt tuyến tính, LangGraph cho phép agent lặp lại, rẽ nhánh, gọi tool nhiều lần và giữ trạng thái xuyên suốt toàn bộ vòng đời.

Nó được xây dựng dựa trên LangChain nhưng giải quyết bài toán khác hẳn: điều phối luồng chạy của agent chứ không phải chỉ kết nối các bước đơn giản.

🔷

Node (Nút)

Một hàm Python thực hiện một tác vụ cụ thể: gọi LLM, chạy tool, xử lý dữ liệu.

➡️

Edge (Cạnh)

Kết nối giữa các node. Có thể là cố định hoặc conditional (phân nhánh theo điều kiện).

📦

State (Trạng thái)

TypedDict dùng chung cho toàn graph. Mỗi node đọc/ghi vào state này.

🔁

Cycle (Vòng lặp)

Graph có thể có chu trình – agent lặp lại nút cho đến khi điều kiện dừng được thỏa mãn.

🛑

Checkpointing

Lưu snapshot state sau mỗi bước. Agent có thể dừng, tiếp tục (Human-in-the-loop).

👥

Multi-Agent

Nhiều graph con (subgraph) giao tiếp với nhau như một hệ thống agent phân tán.

📊 Sơ đồ hoạt động – ReAct Agent

Mô hình phổ biến nhất trong LangGraph: Agent → quyết định gọi Tool hay dừng.

1
Người dùng gửi câu hỏi Input được đưa vào State, graph bắt đầu từ node START.
↓
2
Agent Node (LLM) phân tích LLM đọc state, quyết định: "Cần gọi tool nào?" hoặc "Đã đủ thông tin để trả lời."
↓
3
Conditional Edge phân nhánh Nếu cần tool → chuyển sang Tool Node. Nếu xong → chuyển sang END.
↓
4
Tool Node thực thi Chạy SQL, gọi API, tìm kiếm web... Kết quả được ghi vào State.
↓
5
Vòng lặp quay lại Agent State mới (có kết quả tool) được đưa vào Agent để tiếp tục phân tích. Lặp cho đến khi xong.
↓
6
Trả kết quả cho người dùng Graph kết thúc tại END, state cuối cùng chứa câu trả lời.

📦 State – Trung tâm của LangGraph

State là gì?

State là một TypedDict – từ điển kiểu mạnh – được chia sẻ qua tất cả các node. Mỗi node nhận state cũ, thực hiện thay đổi, trả về phần cập nhật.

LangGraph sử dụng Reducer để merge state: thay vì ghi đè, bạn có thể cộng dồn danh sách messages.

from langgraph.graph import StateGraph
from typing import TypedDict, Annotated
from langchain_core.messages import BaseMessage
import operator

# Định nghĩa State
class AgentState(TypedDict):
    messages: Annotated[
        list[BaseMessage],
        operator.add  # Reducer: cộng dồn
    ]
    user_id: int

# Tạo graph với State
graph = StateGraph(AgentState)

Luồng điều khiển Cố định, A → B → C → D Linh hoạt, có nhánh & vòng lặp
State Management Hạn chế – pass-through, không persistent Mạnh – TypedDict, Reducer, Checkpointing
Vòng lặp (Cycle) Không hỗ trợ natively Hỗ trợ – built-in
Human-in-the-Loop Khó – phải tự implement Dễ – interrupt/resume từ checkpoint
Multi-Agent Cơ bản – AgentExecutor đơn lẻ Mạnh – Subgraph, Supervisor pattern

Use case chính RAG, chatbot đơn giản, summarization Agent phức tạp, long-running, multi-step
Streaming Cơ bản Nâng cao – stream từng node, token, event
Phụ thuộc nhau Độc lập Xây dựng trên LangChain – dùng cùng tools, LLMs

💻 Code mẫu – Expense Tracker AI Agent

Đây là cấu trúc graph được dùng trong backend/app/agents/graph.py của dự án:

# 1. Định nghĩa State
class AgentState(TypedDict):
    messages: Annotated[
        list[BaseMessage], operator.add
    ]
    user_id: int
    thread_id: str

# 2. Tạo các node
def agent_node(state: AgentState):
    # LLM quyết định hành động
    response = llm_with_tools.invoke(
        state["messages"]
    )
    return {"messages": [response]}

# Tool node (SQL, DuckDuckGo...)
tool_node = ToolNode(tools)

# 3. Build Graph
builder = StateGraph(AgentState)

builder.add_node("agent", agent_node)
builder.add_node("tools", tool_node)

builder.add_edge(START, "agent")
builder.add_conditional_edges(
    "agent",
    should_continue,  # hàm phân nhánh
    {
        "tools": "tools",
        "end": END
    }
)
builder.add_edge("tools", "agent")

# 4. Compile với checkpointing
graph = builder.compile(
    checkpointer=memory
)

🗄️ Checkpoint Tables – Bộ nhớ dài hạn của Agent

Khi gọi AsyncPostgresSaver(pool), LangGraph tự động tạo 4 bảng này trong PostgreSQL. Chúng không phải do bạn viết migration — LangGraph quản lý hoàn toàn.

Nhờ 4 bảng này, AI agent nhớ được lịch sử hội thoại giữa các request khác nhau và có thể resume từ giữa chừng nếu server crash.

📸 checkpoints 17 rows

Snapshot toàn bộ State sau mỗi lần một node chạy xong. Mỗi row = 1 checkpoint, tạo thành chuỗi lịch sử của cuộc hội thoại.

  • thread_idID cuộc hội thoại (1 session = 1 thread)
  • checkpoint_idUUID của snapshot này
  • parent_checkpoint_idTrỏ về bước trước → tạo chuỗi lịch sử
  • checkpointJSONB: toàn bộ state (messages, metadata...)
  • metadatastep#, source, user_id, user_lang, currency
🗜️ checkpoint_blobs 11 rows

Data lớn lưu tách riêng dưới dạng binary nén. Tránh bảng checkpoints bị quá nặng khi messages dài.

  • thread_idKhoá liên kết với checkpoints
  • channelTên channel ("messages", "agent_outcome"...)
  • versionPhiên bản của blob này
  • typeKiểu encode: "msgpack", "json"
  • blobbytea: dữ liệu được nén/serialize
✍️ checkpoint_writes 25 rows

Ghi trung gian trong khi 1 node đang chạy. Nếu server crash giữa chừng, LangGraph đọc bảng này để resume chính xác thay vì chạy lại từ đầu.

  • checkpoint_idCheckpoint đang được xử lý
  • task_idTask con đang ghi
  • idxThứ tự ghi trong cùng 1 checkpoint
  • channelState channel bị ghi vào
  • blobGiá trị đang được ghi (binary)
🔢 checkpoint_migrations 10 rows

Version schema của LangGraph — giống alembic_version nhưng dành riêng cho 3 bảng trên. Khi nâng cấp LangGraph, bảng này xác định migration nào cần chạy.

  • vSố thứ tự version (hiện tại: 10 = đã qua 10 migration)

Tương tự alembic_version nhưng do LangGraph tự quản lý, không cần bạn tạo tay.

Luồng hoạt động thực tế trong Expense Tracker

User gửi tin nhắn ai.py tạo hoặc tái sử dụng thread_id cho session này.

Dùng LangChain khi…

  • ✅ Pipeline đơn giản, output dự đoán được
  • ✅ RAG, QA, Summarization
  • ✅ Cần nhanh, ít boilerplate
  • ✅ Team mới làm quen LLM

Dùng LangGraph khi…

  • ✅ Agent cần loop, retry, backtrack
  • ✅ Multi-agent, phân công task
  • ✅ Human review giữa chừng
  • ✅ Long-running, crash recovery
