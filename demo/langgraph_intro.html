1 AI, LLM & AI Agent là gì?

Trước khi vào LangGraph, cần nắm 3 khái niệm xếp lồng nhau: AI → LLM → AI Agent. LangGraph là công cụ để dựng lớp ngoài cùng — Agent.

🧠

AI

Trí tuệ nhân tạo — lĩnh vực rộng giúp máy tính làm việc cần "thông minh": nhận diện, dự đoán, ra quyết định.

💬

LLM

Large Language Model (GPT, Claude, Gemini...). Đoán token tiếp theo, giỏi hiểu & sinh ngôn ngữ — nhưng chỉ trả lời một lượt.

🤖

AI Agent

LLM được trao tool + bộ nhớ + vòng lặp để tự lập kế hoạch & hành động nhiều bước đến khi đạt mục tiêu.

💬 LLM thuần (chatbot)

  • 📥 Nhận prompt → 📤 trả 1 câu trả lời
  • ❌ Không tự gọi API / truy vấn DB
  • ❌ Không nhớ gì giữa các bước
  • ❌ Kiến thức "đóng băng" tại thời điểm train

🤖 AI Agent

  • 🔁 Lặp: suy luận → hành động → quan sát
  • 🔧 Gọi tool: SQL, API, search, code...
  • 📦 Nhớ ngữ cảnh & kết quả qua State
  • 🎯 Tự quyết định khi nào "đã xong"

Một AI Agent gồm 4 thành phần:

🧠

Model (Bộ não)

LLM suy luận & quyết định bước tiếp theo: cần gọi tool nào, hay đã đủ để trả lời.

🔧

Tools (Công cụ)

Hàm để Agent "với tay" ra thế giới thật: truy vấn DB, gọi API, tìm web, tính toán.

📦

Memory (Bộ nhớ)

Lưu lịch sử hội thoại + kết quả tool để Agent không "quên" giữa các bước.

🔁

Loop (Vòng điều khiển)

Điều phối: gọi model → chạy tool → đưa kết quả lại model → lặp đến khi đạt mục tiêu.

💡 LangGraph chính là khung để dựng "Loop + Memory + Tools" đó một cách bài bản — bằng đồ thị có trạng thái. Pattern phổ biến nhất để hiện thực vòng lặp này là ReAct (xem mục 3).

2 LangGraph là gì?

LangGraph là thư viện Python cho phép xây dựng AI Agent dưới dạng đồ thị có trạng thái (stateful directed graph). Thay vì một chuỗi prompt tuyến tính A → B → C, LangGraph cho phép agent lặp lại, rẽ nhánh, gọi tool nhiều lần và nhớ toàn bộ lịch sử.

Nó xây dựng trên LangChain nhưng giải quyết bài toán khác: điều phối luồng chạy của agent — không chỉ kết nối các bước đơn giản.

🔷

Node (Nút)

Hàm Python thực hiện 1 tác vụ: gọi LLM, chạy tool, xử lý data. Nhận State vào, trả về phần State cập nhật.

➡️

Edge (Cạnh)

Kết nối giữa các node. Thường: cố định. Conditional: hàm router quyết định đi node nào tùy theo State.

📦

State (Trạng thái)

TypedDict chia sẻ cho toàn graph. Mọi node đọc/ghi vào đây. Dùng Reducer để merge thay vì ghi đè.

🔁

Cycle (Vòng lặp)

Graph có thể có chu trình. Agent lặp lại node đến khi điều kiện thoát thỏa mãn — đây là điểm khác biệt cốt lõi.

🛑

Checkpointing

Snapshot toàn bộ State sau mỗi bước. Agent có thể dừng, tiếp tục sau (Human-in-the-loop), hoặc resume sau crash.

👥

Multi-Agent

Supervisor điều phối nhiều agent chuyên biệt. Mỗi agent là 1 node (hoặc subgraph) riêng, giao tiếp qua shared State.

3 ReAct Agent – Vòng lặp "Suy luận → Hành động"

ReAct (Reasoning + Acting) là pattern phổ biến nhất: LLM đọc State, quyết định có cần gọi tool không, nếu có thì gọi rồi xem kết quả, lặp cho đến khi đủ thông tin để trả lời.

1
User gửi câu hỏiHumanMessage được thêm vào State. Graph bắt đầu tại START → Agent Node.
2
Agent Node (LLM) phân tíchLLM đọc toàn bộ State (messages, ngữ cảnh). Quyết định: "Cần gọi tool?" hay "Đã đủ để trả lời?"
3
Conditional Edge phân nhánhKiểm tra response: có tool_calls? → sang Tool Node. Không có? → END.
4
Tool Node thực thiChạy tool (SQL query, gọi API, tìm web...). Kết quả ghi vào State dưới dạng ToolMessage.
5
Vòng lặp quay lại AgentState đã có kết quả tool → LLM đọc lại → quyết định tiếp. Lặp cho đến khi không còn tool_calls.
6
END – Trả kết quảAgent ghi câu trả lời vào State. Graph kết thúc. Message cuối được trả về người dùng.

4 Supervisor Pattern – Điều phối nhiều agent

ReAct ở trên là một agent tự lặp. Khi bài toán cần nhiều agent chuyên biệt, ta đặt một Supervisor ở trung tâm: nó đọc State, quyết định agent nào xử lý tiếp (set state["next"]), agent chạy xong trả kết quả về qua shared State, rồi Supervisor lại quyết định — cho đến khi FINISH.

1
Supervisor nhận requestĐọc các message gần nhất trong State, dùng structured tool calling để chọn agent.
2
Conditional edge routeDựa trên state["next"] → đi tới Agent tương ứng. Nếu xong việc → FINISH → END.
3
Agent xử lýAgent chuyên biệt chạy (có thể tự là một ReAct loop riêng), ghi kết quả vào shared State.
4
Quay lại SupervisorAgent trả về Supervisor để điều phối bước tiếp theo — lặp đến khi Supervisor chọn FINISH.

💡 Sơ đồ trên là generic. App này tự viết tay Supervisor (node bind_tools(RouterResponse)) thay vì dùng thư viện langgraph-supervisor. Xem chi tiết cụ thể với 3 agent thật ở Supervisor Pattern → và Phần 2 →.

5 State – Trung tâm của LangGraph

State là gì?

Một TypedDict chia sẻ cho tất cả các node. Mỗi node nhận state cũ, xử lý, trả về partial update.

LangGraph dùng Reducer để merge: field messages dùng operator.add — cộng dồn list thay vì ghi đè, giúp giữ toàn bộ lịch sử hội thoại.

Tại sao quan trọng?

Không có State, mỗi node chỉ nhận output của node trước → không thể loop, không thể nhớ ngữ cảnh, không thể checkpointing.

from langgraph.graph import StateGraph, END, START
from typing import TypedDict, Annotated
from langchain_core.messages import BaseMessage
import operator

# ① Định nghĩa State
class AgentState(TypedDict):
    messages: Annotated[
        list[BaseMessage],
        operator.add    # Reducer: cộng dồn, không ghi đè
    ]
    next: str           # node tiếp theo (dùng trong Supervisor)
    user_id: int

# ② Node function – chỉ trả partial update
def agent_node(state: AgentState):
    response = llm.invoke(state["messages"])
    return {"messages": [response]}  # không cần ghi lại toàn bộ

# ③ Build graph
builder = StateGraph(AgentState)
builder.add_node("agent", agent_node)
builder.add_edge(START, "agent")

# ④ Compile với checkpointing
graph = builder.compile(checkpointer=memory)

6 LangGraph vs LangChain

Tiêu chí ⛓️ LangChain 🔷 LangGraph
Mô hình luồng Chuỗi tuyến tính: A → B → C Đồ thị có hướng, nhánh & vòng lặp
Vòng lặp (Cycle) Không – không hỗ trợ natively Có – built-in, qua conditional edge
State quản lý Hạn chế – pass-through, không persistent Mạnh – TypedDict + Reducer + Checkpointing
Human-in-the-Loop Khó – phải tự implement Dễ – interrupt/resume từ checkpoint
Multi-Agent Cơ bản – AgentExecutor đơn lẻ Mạnh – Subgraph, Supervisor pattern
Độ phức tạp Thấp – ít boilerplate, dễ học Trung bình – cần hiểu Graph, State, Reducer
Use case chính RAG, QA, Summarization, pipeline cố định Agent phức tạp, multi-step, long-running
Quan hệ Độc lập Xây trên LangChain – dùng chung tools, LLMs, prompts

⛓️ Dùng LangChain khi:

  • ✅ Pipeline đơn giản, output dự đoán được
  • ✅ RAG, Document QA, Summarization
  • ✅ Prototype nhanh, ít boilerplate
  • ✅ Team mới bắt đầu với LLM

🔷 Dùng LangGraph khi:

  • ✅ Agent cần loop, retry, tự sửa lỗi
  • ✅ Nhiều agent phối hợp (supervisor)
  • ✅ Cần human review giữa chừng
  • ✅ Long-running, crash recovery
