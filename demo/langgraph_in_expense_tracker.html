2 Chi tiết 2 Nodes

App gồm 2 node: agent (LLM) và tools (ToolNode). Toàn bộ logic "làm gì tiếp theo" do chính LLM quyết định qua tool calling — agent xuất tool_calls để dùng tool, hoặc trả lời để kết thúc.

🧠 agent Entry Point

LLM được bind toàn bộ tool (giao dịch + đọc + SQL read-only + web search). Mỗi lượt nó đọc history + system prompt (đã nhúng ngày, categories, tiền tệ, user_id) rồi xuất hoặc tool_calls (cần dùng tool) hoặc câu trả lời cuối. An toàn (từ chối phá hoại / lộ .env) đến từ system prompt + giới hạn của tool.

có tool_calls → tools
không còn tool call (trả lời text) → END
🔧 tools
ToolNode

LangGraph's ToolNode — nhìn AIMessage.tool_calls, thực thi tool, ghi ToolMessage vào State, rồi luôn quay về agent để LLM đọc kết quả và quyết bước kế (đây chính là vòng ReAct). Đặc biệt: nếu một tool gọi interrupt() (ngoại tệ trong submit_expense_tool, hoặc ask_clarification_tool), graph tạm dừng ngay tại đây chờ Command(resume)

3 Toolset của Agent (12 tools)

Một agent duy nhất sở hữu cả 12 tool (gộp lúc build trong agent.py): tool giao dịch/đọc bind theo user_id + user_currency (make_tools), bộ SQL read-only user-scoped (make_sql_tools) và web search. Hai nhóm dưới chỉ để dễ đọc — với LLM tất cả nằm chung một danh sách.

📊 SQL & web research — 5 tools

Bộ SQLDatabaseToolkit + web search từ analyst.py (make_sql_tools). Toolkit chỉ expose 3 bảng expenses, categories, incomes; bản sql_db_query gốc bị thay bằng bản guarded: chỉ cho SELECT (chặn DROP/DELETE/...), ép user-scoping, và chặn hẳn các bảng nhạy cảm (users, jars, recurring_expenses). SQL ưu tiên chạy qua role read-only analyst_ro (RLS), fallback về owner engine khi chưa cấu hình.

4 Checkpoint – Bộ nhớ dài hạn của Agent

Khi gọi AsyncPostgresSaver(pool), LangGraph tự tạo 4 bảng trong PostgreSQL — không cần viết migration thủ công. Nhờ đây, agent nhớ lịch sử hội thoại giữa các request và có thể resume sau crash.

📸 checkpoints Core

Snapshot toàn bộ State sau mỗi node. Mỗi row = 1 bước, liên kết thành chuỗi lịch sử qua parent_id.

  • thread_idID cuộc hội thoại (UUID)
  • checkpoint_idUUID của snapshot này
  • parent_checkpoint_idTrỏ về bước trước → chuỗi lịch sử
  • checkpointJSONB: toàn bộ state
  • metadatastep#, source, user_id, currency
🗜️ checkpoint_blobs Storage

Data lớn lưu tách riêng dưới dạng binary nén. Tránh bảng checkpoints quá nặng khi messages dài.

  • thread_idKhóa liên kết
  • channel"messages", "agent_outcome"...
  • versionPhiên bản của blob
  • type"msgpack" hoặc "json"
  • blobbytea: dữ liệu serialize/nén
✍️ checkpoint_writes WAL

Ghi trung gian khi node đang chạy. Nếu server crash, LangGraph đọc bảng này để resume chính xác.

  • checkpoint_idCheckpoint đang xử lý
  • task_idTask con đang ghi
  • idxThứ tự ghi
  • channelState channel bị write
  • blobGiá trị đang ghi (binary)
🔢 checkpoint_migrations Schema

Version schema - LangGraph tự quản lý.

Khi upgrade LangGraph, bảng này quyết định migration nào cần chạy thêm.

5 Human-in-the-Loop (HITL)

Có lúc agent cần hỏi lại user giữa chừng rồi mới làm tiếp — ví dụ chi tiêu bằng ngoại tệ thì phải biết tỷ giá. LangGraph cho việc này bằng cặp primitive interrupt() & Command(resume=...): interrupt() tạm dừng graph ngay tại chỗ đang chạy và ghi state xuống checkpointer; lượt sau gọi Command(resume=<đáp án>) thì graph chạy tiếp đúng điểm dừng, không khởi động lại từ đầu.
