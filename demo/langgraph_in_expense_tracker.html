1 Kiến trúc tổng quan

Graph trong app dùng Supervisor Pattern: một node trung tâm phân tích câu hỏi và phân công cho agent chuyên biệt. Toàn bộ flow được định nghĩa trong backend/app/agents/graph.py.

Graph có 5 nodes, mỗi node xử lý một loại tác vụ khác nhau. Supervisor quyết định node nào chạy tiếp theo bằng cách set state["next"].

2 Chi tiết 5 Nodes

🎯 supervisor_node Entry Point

LLM đọc 10 messages gần nhất, dùng structured tool calling để quyết định route. Trả về state["next"] là một trong 4 giá trị: "financial_agent", "data_analyst", "general_agent", "FINISH".

Logic đặc biệt: Nếu message cuối là AIMessage (agent vừa trả lời), Supervisor tự động set FINISH — tránh agent gọi agent vô hạn.

💰 financial_agent

Xử lý giao dịch tài chính

Gọi LLM với 7 tools để thêm chi tiêu, thu nhập, kiểm tra ngân sách. Có tool loop nội bộ với financial_tools.

Nếu LLM trả về tool_calls → financial_tools
Nếu không có → supervisor

Phân tích & tổng hợp dữ liệu

Wrap get_analyst_agent() từ analyst.py — agent riêng chuyên chạy SQL và tìm kiếm web.

Sau khi xử lý xong → luôn về supervisor
💬 general_agent

Xử lý chitchat

LLM trực tiếp, không có tools. Xử lý lời chào, câu hỏi ngoài chủ đề tài chính. Temperature 0.5 để tự nhiên hơn.

Sau khi trả lời → về supervisor
🔧 financial_tools
ToolNode

Là LangGraph's ToolNode — tự động nhìn vào AIMessage.tool_calls, tìm đúng tool function và thực thi, ghi kết quả vào State dưới dạng ToolMessage. Sau đó luôn quay về financial_agent để LLM đọc kết quả.

3 8 Tools của Financial Agent

Tất cả được tạo qua factory make_tools(user_id) trong backend/app/agents/tools.py. Mỗi tool được bind với user_id — đảm bảo data isolation.

Read
lookup_categories_tool
Lấy danh sách category của user. Bắt buộc gọi trước khi log expense — không được dùng tên category từ bộ nhớ.
Write
submit_expense_tool
Tạo draft expense. Trả về chuỗi "Draft Created|category_id:X|..." để API layer parse và lưu DB thực.
Write
submit_income_tool
Tạo draft income với amount và source. Trả về tín hiệu hoàn thành để frontend hiển thị form confirm.
Check
check_budget_tool
Kiểm tra nếu chi thêm X vào category Y có vượt budget không. Trả về cảnh báo hoặc xác nhận an toàn.
Read
get_monthly_summary_tool
Tổng chi tiêu và breakdown theo category cho một tháng. Dùng khi user hỏi "tháng này tôi chi bao nhiêu?"
Read
get_recent_expenses_tool
10 expense gần nhất trong N ngày qua (default 7). Dùng để kiểm tra expense đã thêm chưa.
Read
get_recent_incomes_tool
20 income gần nhất trong N ngày qua (default 30). Dùng khi user hỏi về thu nhập gần đây.
External
search_web_tool
Tìm kiếm DuckDuckGo. Dùng khi cần tỷ giá thời gian thực hoặc thông tin tài chính bên ngoài.

4 Checkpoint – Bộ nhớ dài hạn của Agent

Khi gọi AsyncPostgresSaver(pool), LangGraph tự tạo 4 bảng trong PostgreSQL — không cần viết migration thủ công. Nhờ đây, agent nhớ lịch sử hội thoại giữa các request và có thể resume sau crash.

📸 checkpoints Core

Snapshot toàn bộ State sau mỗi node. Mỗi row = 1 bước, liên kết thành chuỗi lịch sử qua parent_id.

  • thread_idID cuộc hội thoại (UUID)
  • checkpoint_idUUID của snapshot này
  • parent_checkpoint_idTrỏ về bước trước → chuỗi lịch sử
  • checkpointJSONB: toàn bộ state
  • metadatastep#, source, user_id, currency
🗜️ checkpoint_blobs Storage

Data lớn lưu tách riêng dưới dạng binary nén. Tránh bảng checkpoints quá nặng khi messages dài.

  • thread_idKhóa liên kết
  • channel"messages", "agent_outcome"...
  • versionPhiên bản của blob
  • type"msgpack" hoặc "json"
  • blobbytea: dữ liệu serialize/nén
✍️ checkpoint_writes WAL

Ghi trung gian khi node đang chạy. Nếu server crash, LangGraph đọc bảng này để resume chính xác.

  • checkpoint_idCheckpoint đang xử lý
  • task_idTask con đang ghi
  • idxThứ tự ghi
  • channelState channel bị write
  • blobGiá trị đang ghi (binary)
🔢 checkpoint_migrations Schema

Version schema — giống alembic_version nhưng dành riêng cho 3 bảng trên. LangGraph tự quản lý.

  • vSố thứ tự migration (ví dụ: 10)

Khi upgrade LangGraph, bảng này quyết định migration nào cần chạy thêm.

💡 Tại sao quan trọng? Không có checkpointing, mỗi request tới POST /api/ai/agent/chat sẽ là hội thoại mới hoàn toàn. Với checkpointing, user có thể hỏi "tháng trước tôi chi bao nhiêu?" rồi tiếp ngay "so với tháng này thì sao?" — agent hiểu được ngữ cảnh nhờ đọc lại checkpoint theo thread_id.
