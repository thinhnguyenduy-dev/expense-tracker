1 Kiến trúc tổng quan

Graph trong app dùng Supervisor Pattern: một node trung tâm phân tích câu hỏi và phân công cho agent chuyên biệt. Wiring của graph nằm trong backend/app/agents/graph.py; các node ở nodes.py, prompt ở prompts.py, schema State ở state.py, helper xử lý message ở utils.py.

Graph có 6 nodes: supervisor, financial_agent, financial_tools, clarification_node, data_analyst, general_agent. Supervisor chỉ điều phối 3 agent — financial_agent, data_analyst, general_agent — bằng cách set state["next"] (hoặc FINISH → END). Hai node phụ trợ financial_tools và clarification_node thuộc vòng nội bộ của financial_agent (đi bằng conditional edge riêng), không do supervisor chọn. Shared AgentState (state.py) gồm 4 field: messages (reducer operator.add), clarification_needed, next, analyst_trace — còn user_id/thread_id nằm trong config["configurable"], không phải State.

2 Chi tiết 6 Nodes

🎯 supervisor_node Entry Point

LLM đọc 10 messages gần nhất (đã sanitize), dùng structured tool calling (bind_tools(RouterResponse, tool_choice="RouterResponse")) để quyết định route. RouterResponse có 2 field: next — một trong "financial_agent", "data_analyst", "general_agent", "FINISH" — và reason (khi FINISH, được thêm vào history dưới dạng AIMessage để UI thấy).

Logic đặc biệt: Nếu message cuối là AIMessage (agent vừa trả lời), Supervisor tự động set FINISH — tránh agent gọi agent vô hạn.

🔧 financial_tools
ToolNode

Bọc LangGraph's ToolNode — nhìn vào AIMessage.tool_calls, thực thi tool, ghi ToolMessage vào State. Đặc biệt: nếu phát hiện ask_clarification_tool, nó surface câu hỏi vào clarification_needed. Sau đó luôn quay về financial_agent.

🛑 clarification_node
Terminal

Node kết thúc graph (→ END) khi AI cần hỏi thêm. Không gọi LLM — chỉ là điểm thoát. ai.py đọc clarification_needed trong final_state → trả needs_clarification=True. Câu trả lời của user ở lượt sau đến như HumanMessage mới và financial_agent resume.

🛑 Clarification & Resume — khi AI cần hỏi lại

Khi yêu cầu mơ hồ (nhiều khoản chi trong 1 câu, category không rõ, hoặc số tiền ở ngoại tệ), financial_agent gọi ask_clarification_tool. Thay vì dùng interrupt(), app cho graph kết thúc sạch tại clarification_node và trả needs_clarification=True về frontend. Lượt sau, frontend gọi lại với is_resume=true → bơm RESUME_INSTRUCTION vào prompt để agent bắt buộc submit, không hỏi lại.

🧹 data_analyst trả về gì cho Supervisor? — last_message vs full_history

data_analyst là một ReAct subgraph riêng: khi chạy nó tự sinh ra cả chuỗi AI → Tool → AI → Tool (mỗi vòng truy vấn SQL). Câu hỏi thiết kế: đẩy toàn bộ chuỗi đó về shared State (full_history), hay chỉ đẩy message cuối (last_message)? App này chọn last_message.

💡 Mode được chọn qua settings.ANALYST_OUTPUT_MODE (mặc định last_message) và truyền vào config["configurable"]["analyst_output_mode"]. Ở last_message, data_analyst_node đẩy về shared State đúng 1 message cuối (return {"messages": [new_messages[-1]], ...}) — Supervisor không bị ngập trong tool-call SQL nội bộ. Không mất khả năng truy vết: chuỗi AI/Tool nội bộ được trích riêng bằng _extract_tool_trace() và lưu vào field analyst_trace của State; ai.py gộp nó vào tool_calls để UI vẫn hiện được các bước SQL. Mode full_history thì merge thẳng mọi message analyst sinh ra (slice off phần history đã có để operator.add không nhân đôi).

3 7 Tools của Financial Agent

Tất cả được tạo qua factory make_tools(user_id, user_currency) trong backend/app/agents/tools.py. Mỗi tool được bind với user_id (data isolation) và user_currency (format tiền tệ đúng — VND/JPY/KRW không có phần thập phân).

Write
submit_expense_tool
Tạo draft expense. Categories được truyền qua system prompt (không cần gọi tool lookup). Trả về "Draft Created|...".
Write
submit_income_tool
Tạo draft income với amount và source. Trả về tín hiệu hoàn thành để frontend hiển thị form confirm.
Clarify
ask_clarification_tool
Hỏi user khi thiếu thông tin (category không rõ, amount mơ hồ). Graph tạm dừng, đợi user trả lời, sau đó resume.
Read
get_monthly_summary_tool
Tổng chi tiêu và breakdown theo category cho một tháng. Dùng khi user hỏi "tháng này tôi chi bao nhiêu?"
Read
get_monthly_income_summary_tool
Tổng thu nhập và breakdown theo nguồn (source) cho một tháng. Dùng khi user hỏi "tháng này tôi kiếm được bao nhiêu?"
Read
get_recent_expenses_tool
10 expense gần nhất trong N ngày qua (default 7). Dùng để kiểm tra expense đã thêm chưa.
Read
get_recent_incomes_tool
20 income gần nhất trong N ngày qua (default 30). Dùng khi user hỏi về thu nhập gần đây.

🔁 Ngoại tệ / web search: Financial agent không có tool search web. Nếu khoản chi ở ngoại tệ (USD, EUR…), prompt bắt agent gọi ask_clarification_tool một lần để hỏi tỷ giá, rồi tự quy đổi (amount × rate) khi resume — không bao giờ submit ngoại tệ khi chưa có rate xác nhận. Quy đổi deterministic ở tầng API do ExchangeRateService xử lý; tìm kiếm web (DuckDuckGo) là việc của data_analyst.

⚡ Optimization: Categories được fetch 1 lần ở API level (process_chat) và truyền vào config["configurable"]["categories"]. Financial agent nhận list này qua system prompt — giảm 33% LLM calls so với việc gọi lookup_categories_tool mỗi request.

4 Checkpoint – Bộ nhớ dài hạn của Agent

Khi gọi AsyncPostgresSaver(pool), LangGraph tự tạo 4 bảng trong PostgreSQL — không cần viết migration thủ công. Nhờ đây, agent nhớ lịch sử hội thoại giữa các request và có thể resume sau crash.

📸 checkpoints Core

Snapshot toàn bộ State sau mỗi node. Mỗi row = 1 bước, liên kết thành chuỗi lịch sử qua parent_id.

  • thread_idID cuộc hội thoại (UUID)
  • checkpoint_idUUID của snapshot này
  • parent_checkpoint_idTrỏ về bước trước → chuỗi lịch sử
  • checkpointJSONB: toàn bộ state
  • metadatastep#, source, user_id, currency
🗜️ checkpoint_blobs Storage

Data lớn lưu tách riêng dưới dạng binary nén. Tránh bảng checkpoints quá nặng khi messages dài.

  • thread_idKhóa liên kết
  • channel"messages", "agent_outcome"...
  • versionPhiên bản của blob
  • type"msgpack" hoặc "json"
  • blobbytea: dữ liệu serialize/nén
✍️ checkpoint_writes WAL

Ghi trung gian khi node đang chạy. Nếu server crash, LangGraph đọc bảng này để resume chính xác.

  • checkpoint_idCheckpoint đang xử lý
  • task_idTask con đang ghi
  • idxThứ tự ghi
  • channelState channel bị write
  • blobGiá trị đang ghi (binary)
🔢 checkpoint_migrations Schema

Version schema — giống alembic_version nhưng dành riêng cho 3 bảng trên. LangGraph tự quản lý.

  • vSố thứ tự migration (ví dụ: 10)

Khi upgrade LangGraph, bảng này quyết định migration nào cần chạy thêm.

💡 Tại sao quan trọng? Không có checkpointing, mỗi request tới POST /api/ai/agent/chat sẽ là hội thoại mới hoàn toàn. Với checkpointing, user có thể hỏi "tháng trước tôi chi bao nhiêu?" rồi tiếp ngay "so với tháng này thì sao?" — agent hiểu được ngữ cảnh nhờ đọc lại checkpoint theo thread_id.
