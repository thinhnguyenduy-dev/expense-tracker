LangGraph trong Expense Tracker

1 Kiến trúc tổng quan

Graph trong app dùng Supervisor Pattern: một node trung tâm phân tích câu hỏi và phân công cho agent chuyên biệt.

2 Chi tiết 6 Nodes

🎯 supervisor_node Entry Point

LLM đọc 10 messages gần nhất (đã sanitize), dùng structured tool calling (bind_tools(RouterResponse, tool_choice="RouterResponse")) để quyết định route. RouterResponse có 2 field: next — một trong "financial_agent", "data_analyst", "general_agent", "FINISH" — và reason (khi FINISH, được thêm vào history dưới dạng AIMessage để UI thấy).

💰 financial_agent

Xử lý giao dịch tài chính

Gọi LLM với 7 tools để thêm chi tiêu, thu nhập, xem tổng hợp tháng. Có tool loop nội bộ với financial_tools. Cũng chạy clarification relay & resume mode

💬 general_agent

Xử lý chitchat

LLM trực tiếp, không có tools. Xử lý lời chào, câu hỏi ngoài chủ đề tài chính.

Sau khi trả lời → về supervisor
🔧 financial_tools
ToolNode

Bọc LangGraph's ToolNode — nhìn vào AIMessage.tool_calls, thực thi tool, ghi ToolMessage vào State. Đặc biệt: nếu phát hiện ask_clarification_tool, nó surface câu hỏi vào clarification_needed. Sau đó luôn quay về financial_agent.

🛑 clarification_node
Terminal

Node kết thúc graph (→ END) khi AI cần hỏi thêm. Không gọi LLM — chỉ là điểm thoát. ai.py đọc clarification_needed trong final_state → trả needs_clarification=True. Câu trả lời của user ở lượt sau đến như HumanMessage mới và financial_agent resume.

4 Checkpoint – Bộ nhớ dài hạn của Agent

Khi gọi AsyncPostgresSaver(pool), LangGraph tự tạo 4 bảng trong PostgreSQL — không cần viết migration thủ công. Nhờ đây, agent nhớ lịch sử hội thoại giữa các request và có thể resume sau crash.

📸 checkpoints Core

Snapshot toàn bộ State sau mỗi node. Mỗi row = 1 bước, liên kết thành chuỗi lịch sử qua parent_id.

  • thread_idID cuộc hội thoại (UUID)
  • checkpoint_idUUID của snapshot này
  • parent_checkpoint_idTrỏ về bước trước → chuỗi lịch sử
  • checkpointJSONB: toàn bộ state
  • metadatastep#, source, user_id, currency
🗜️ checkpoint_blobs Storage

Data lớn lưu tách riêng dưới dạng binary nén. Tránh bảng checkpoints quá nặng khi messages dài.

  • thread_idKhóa liên kết
  • channel"messages", "agent_outcome"...
  • versionPhiên bản của blob
  • type"msgpack" hoặc "json"
  • blobbytea: dữ liệu serialize/nén
✍️ checkpoint_writes WAL

Ghi trung gian khi node đang chạy. Nếu server crash, LangGraph đọc bảng này để resume chính xác.

  • checkpoint_idCheckpoint đang xử lý
  • task_idTask con đang ghi
  • idxThứ tự ghi
  • channelState channel bị write
  • blobGiá trị đang ghi (binary)
🔢 checkpoint_migrations Schema

Version schema - LangGraph tự quản lý.

Khi upgrade LangGraph, bảng này quyết định migration nào cần chạy thêm.

5 Luồng API – từ Request đến Response

Frontend gửi request { message, thread_id?, is_resume } — thread_id là UUID nhận từ response trước (null → tạo mới). is_resume=true khi user đang trả lời câu hỏi clarification.
Lấy preferences + categories Query DB lấy user_lang, user_currency và danh sách categories (1 lần). Cùng với analyst_output_mode & is_resume, tất cả đưa vào config.configurable; AILoggingCallbackHandler gắn vào config.callbacks.
Tạo AsyncPostgresSaver Mở connection pool → tạo checkpointer → compile graph với checkpointer đã attach.
AsyncPostgresSaver(pool)
LangGraph đọc checkpoint cũ Tìm checkpoint mới nhất theo thread_id → khôi phục messages, ngữ cảnh trước đó vào State.
READ checkpoints
graph.ainvoke() – chạy toàn bộ graph Supervisor → agent → (tools loop) → Supervisor → FINISH. recursion_limit=12 để tránh vòng lặp vô hạn.
Trả response + thread_id Nếu final_state có clarification_needed → trả needs_clarification=True ngay. Ngược lại parse các message mới: gom nhiều submit_expense_tool thành list, detect income, gộp analyst_trace vào tool_calls. GraphRecursionError → trả lời an toàn.
