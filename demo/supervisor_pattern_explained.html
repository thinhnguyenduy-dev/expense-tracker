📚 1. Supervisor Pattern là gì?

💡 Định Nghĩa

Supervisor Pattern là kiến trúc multi-agent trong đó:

  • 🎯 1 Supervisor node: Node trung tâm phân tích request và routing
  • 👷 N Agents: Các agent chuyên biệt xử lý từng loại task
  • 🔄 Cyclic flow: Agents hoàn thành → về Supervisor → routing tiếp (nếu cần)
📌 Mục đích: Chia nhỏ công việc phức tạp cho các agent chuyên môn cao, giảm token cost, và tăng chất lượng output.

🎯 3. Supervisor Node - Trái Tim của Pattern

File: backend/app/agents/graph.py

def supervisor_node(state: AgentState): """Decides which agent to route to.""" model = get_llm(temperature=0) system_prompt = ( "You are a supervisor for a Financial App. " "Your goal is to route the conversation or finish it.\n" "WORKERS:\n" "1. `financial_agent`: For expenses/incomes/budget\n" "2. `data_analyst`: For analytics/aggregation/SQL\n" "3. `general_agent`: For greetings\n" ) # Structured output với Pydantic class RouterResponse(BaseModel): next: Literal["financial_agent", "data_analyst", "general_agent", "FINISH"] reason: Optional[str] # Gọi LLM với tool calling model_with_tool = model.bind_tools([RouterResponse]) response = model_with_tool.invoke([ SystemMessage(content=system_prompt), *messages[-10:] # Context window ]) # Extract routing decision next_node = response.tool_calls[0]["args"]["next"] return {"next": next_node}
✅ Key Points:
  • Supervisor nhận AgentState với messages history
  • LLM phân tích và quyết định routing
  • Return {"next": "agent_name"}
  • Conditional edge đọc state["next"] để routing

🔄 5. Flow Chi Tiết: User Gửi Request

Scenario: "Tôi vừa mua cà phê 50k"

1 START → Supervisor
# Entry point luôn là supervisor workflow.set_entry_point("supervisor") # State ban đầu: { "messages": [HumanMessage("Tôi vừa mua cà phê 50k")] }
2 Supervisor Phân Tích
# Supervisor gọi LLM: # Input: "Tôi vừa mua cà phê 50k" # LLM phân tích: User muốn log expense → Route financial_agent # Supervisor return: { "messages": [AIMessage("Routing to financial agent")], "next": "financial_agent" ← Key routing! }
3 Conditional Edge Routing
# File: graph.py workflow.add_conditional_edges( "supervisor", lambda state: state["next"], ← Đọc state["next"] { "financial_agent": "financial_agent", ← Nếu "financial_agent" → chuyển đến node đó "data_analyst": "data_analyst", "general_agent": "general_agent", "FINISH": END } ) # state["next"] = "financial_agent" → Chuyển sang financial_agent_node
4 Financial Agent Xử Lý
# financial_agent nhận categories từ config # Gọi submit_expense_tool(amount=50000, category="Cà phê") # Tool return: "Draft Created" # Agent return: { "messages": [AIMessage("Đã ghi chi tiêu Cà phê 50k!")] }
5 Back to Supervisor
# Conditional edge từ financial_agent: def should_continue_financial(state): last_message = state["messages"][-1] if getattr(last_message, "tool_calls", None): return "financial_tools" # Có tool_calls → gọi tools return "supervisor" ← Xong → về supervisor # Không còn tool_calls → Quay về supervisor
6 Supervisor Quyết Định Kết Thúc
# Supervisor thấy AIMessage từ agent (không phải HumanMessage) if last_msg.type == "ai": return {"next": "FINISH"} ← Tránh loop vô hạn # Conditional edge: "FINISH" → END # Graph kết thúc!

⚙️ 6. Workflow Setup

File: backend/app/agents/graph.py

def get_agent_graph(): workflow = StateGraph(AgentState) # ── Thêm Nodes ──────────────────────── workflow.add_node("supervisor", supervisor_node) workflow.add_node("financial_agent", financial_agent_node) workflow.add_node("financial_tools", financial_tools_node) workflow.add_node("data_analyst", data_analyst_node) workflow.add_node("general_agent", general_agent_node) workflow.add_node("clarification_node", clarification_node) # ── Entry Point ─────────────────────── workflow.set_entry_point("supervisor") ← Luôn bắt đầu ở supervisor # ── Conditional Edge: Supervisor Routing ──── workflow.add_conditional_edges( "supervisor", lambda state: state["next"], ← Đọc state["next"] { "financial_agent": "financial_agent", "data_analyst": "data_analyst", "general_agent": "general_agent", "FINISH": END } ) # ── Agents về Supervisor ──────────── workflow.add_edge("data_analyst", "supervisor") workflow.add_edge("general_agent", "supervisor") # financial_agent có conditional edge phức tạp hơn return workflow
✅ Pattern Core:
  • Entry point = supervisor
  • Conditional edge từ supervisor routing đến agents
  • Agents return về supervisor (hoặc END)
  • Cyclic flow cho phép multi-turn conversation

🆚 7. So Sánh: Supervisor vs Sequential

❌ Sequential Pattern

Agent A → Agent B → Agent C → END

• Cố định, không linh hoạt
• Mọi request đều đi qua tất cả agents
• Tốn token không cần thiết
• Không thể skip agents

✅ Supervisor Pattern

           ┌─ Agent A
Supervisor ┼─ Agent B
           └─ Agent C

• Dynamic routing theo request
• Chỉ gọi agent cần thiết
• Tiết kiệm token
• Supervisor có thể routing nhiều lần

💡 8. Lợi Ích của Supervisor Pattern

Lợi Ích Giải Thích Trong Expense Tracker
🎯 Specialization Mỗi agent chuyên 1 việc financial_agent = transactions, data_analyst = analytics
💰 Token Efficiency Chỉ gọi agent cần thiết "Xin chào" → general_agent (không cần financial tools)
🔄 Flexibility Dynamic routing Supervisor quyết định runtime dựa trên context
📦 Scalability Thêm agent dễ dàng Thêm "export_agent" chỉ cần update supervisor routing
🧩 Maintainability Separation of concerns Sửa financial logic không ảnh hưởng data_analyst
🔁 Multi-turn Cyclic conversation User hỏi → analyst → User hỏi tiếp → financial_agent

⚠️ 9. Challenges & Solutions

Challenge 1: Infinite Loop

⚠️ Vấn đề: Supervisor routing agent → agent return → supervisor routing lại → loop vô hạn!
✅ Giải pháp: Check last message type
if last_msg.type == "ai": # Last message từ agent → Không routing nữa return {"next": "FINISH"}

Challenge 2: Routing Accuracy

⚠️ Vấn đề: LLM routing sai agent → Bad user experience
✅ Giải pháp: Clear system prompt với examples
"CRITICAL ROUTING RULES: - 'total expenses' → data_analyst - 'log expense' → financial_agent - 'hello' → general_agent"

Challenge 3: State Management

⚠️ Vấn đề: Nhiều agents update cùng State → Conflict?
✅ Giải pháp: TypedDict + Reducer pattern
# messages: Merge với operator.add # next: Overwrite (chỉ cần mới nhất) # → Không conflict!

✅ 10. Tóm Tắt

Key Takeaways:

Khái Niệm Giải Thích
Supervisor Pattern 1 supervisor + N agents, dynamic routing
Supervisor Node Phân tích request, set state["next"], routing
Agents Chuyên môn cao, xử lý task cụ thể
Conditional Edge Đọc state["next"] để routing động
Cyclic Flow Agents → Supervisor → Agents... (multi-turn)
Entry Point Luôn là supervisor
Lợi ích Token efficiency, flexibility, scalability

🎓 Kết Luận

Supervisor Pattern là kiến trúc tối ưu cho multi-agent systems phức tạp. Nó kết hợp sức mạnh của nhiều agents chuyên biệt với routing thông minh.

Trong Expense Tracker, pattern này cho phép:

  • ✅ Financial agent xử lý transactions với 8 tools
  • ✅ Data analyst phân tích dữ liệu với SQL
  • ✅ General agent xử lý chitchat nhẹ nhàng
  • ✅ Supervisor routing thông minh, tiết kiệm token
